# 支持格式与真实限制

“可提取”指能够读取部分正文，不代表保持版式或正确理解全部内容。此项目使用轻量解析，没有调用 Office、运行宏或执行文档脚本。

| 类型 | 支持范围 | 不能保证的内容 |
| --- | --- | --- |
| TXT、Markdown、代码、JSON、CSV/TSV、YAML 等 | UTF-8；带 BOM 的 UTF-16 LE/BE | 不自动识别 GBK 等传统编码；CSV 不做类型推断 |
| HTML/HTM/XHTML | 静态文字，移除脚本、样式等 | 不运行 JavaScript、不访问网络、不还原动态页面 |
| DOCX/DOCM/DOTX/DOTM | `word/document.xml` 中的基本正文 | 页眉页脚、批注、修订语义、图片、布局；宏不执行 |
| XLSX/XLSM/XLTX/XLTM | 基础共享字符串、内联字符串、缓存数值，保留列间空位 | 不计算公式；缓存可能过时；日期可能是序列数；合并单元格、隐藏状态、图表、空白行和显示格式不保真；工作表显示内部编号 |
| PPTX/PPTM/POTX/POTM/PPSX/PPSM | 幻灯片文本，按 slide 数字排序 | 备注、图片、图表、视觉布局和复杂阅读顺序 |
| PDF | 部分文字操作符和 Flate 压缩流 | **有限支持**：无 OCR、缺少字体到 Unicode 映射；不少中文/复杂 PDF 即使成功也可能乱码或漏字 |
| ODT/ODS/ODP/OTT/OTS/OTP | `content.xml` 基本文字 | 表格坐标、重复行列、布局等不完整 |
| EPUB | 包内 HTML/XHTML 正文 | 按文件名排序，不按阅读器的 spine 顺序；不支持 DRM |
| RTF | 基础控制码和文字 | 复杂分组、代码页、嵌入对象等不完整 |
| PNG、JPG/JPEG/JPE | 宽高元数据 | **不识图、不 OCR、不向模型传图片像素** |

旧式二进制 `.doc/.xls/.ppt`、密码保护文档、音视频、数据库和通用压缩包内容不在支持承诺内。未知扩展名只尝试严格文本解码，不代表支持它的二进制格式。文件只要能解码也未必具有预期语义。

## 大小与解压限制

- 单次读文件最大 20 MiB，正文分段返回最多 100,000 个 UTF-16 代码单元。
- 搜索单文件最大 5 MiB；其他搜索预算见[使用手册](USER-GUIDE.md)。
- ZIP 类文档最多 5,000 项，累计解压数据最多 10 MiB；只支持 stored/deflate，不支持加密或 ZIP64。不是通用 ZIP 修复/验证工具。
- PDF 所有已处理流累计展开最多 10 MiB，Excel 提取文字也受输出规模限制。
- 有大小上限不等于有严格 CPU 时间/内存隔离；恶意复杂文档仍可能造成等待，应使用可信静态副本。

## 遇到乱码、漏字怎么办

文本先另存为 UTF-8，再读取副本。Office 旧格式先由原应用导出为新版格式或文本。复杂 PDF、扫描件、复杂表格应考虑专业转换/OCR 后将结果放入授权目录，并抽样与原件核对。

后续可将 MarkItDown 或 Docling 做成明确启用的本地解析选项，保留同一授权边界。它们不在当前依赖或安装包中，详见[比较与路线](COMPARISON.md)。
