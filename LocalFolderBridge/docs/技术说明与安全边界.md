# 技术说明与安全边界

**Local Folder Bridge 1.1.x｜基线 2026-09-13；维护复核 2026-09-29**

## 1. 产品定位与实现选择

本程序是私有、本机、面向工具调用的文件桥。浏览器界面只管理本机授权和审批；ChatGPT 调用的是独立 MCP 服务，不是浏览器 DOM。设计目标是让用户完整解压后双击启动，并保留可审计源码、可重跑测试和明确的权限边界。

早期方案优先建议官方 Python MCP SDK；最终交付为降低 Windows 首次启动依赖，使用标准库实现受限的 **tools-only 协议适配层**。这不是“已集成完整官方 SDK”，也不声称覆盖 MCP 全部功能。文件能力与协议适配分离在 `engine.py` / `protocol.py`，以后需要完整 SDK、会话订阅、OAuth 或嵌入式 ChatGPT UI 时，应替换适配层并重做兼容性测试。

当前支持 `2025-11-25`、`2025-06-18`、`2025-03-26` 三个明确协议版本的协商、JSON-RPC 初始化/工具发现/调用、stdio 和 JSON 响应模式 Streamable HTTP。没有公共 OAuth、SSE 推送、资源订阅、sampling、elicitation、远程 shell 或管理界面资源嵌入。客户端请求未知协议时协商回已实现版本；不是对未来协议自动兼容的承诺。依据：<https://modelcontextprotocol.io/specification/2025-11-25/basic/transports>。

## 2. 数据路径与模块职责

```text
ChatGPT 开发者插件
    │ 相同 Tunnel ID / 工作区关联
OpenAI Secure MCP Tunnel
    │ 官方 tunnel-client 主动建立出站链路
本机 tunnel-client 子进程
    │ 仅 localhost，独立 MCP Bearer 凭证
127.0.0.1:18766/mcp
    │ Protocol → Engine → Path policy → 隔离解析进程
明确授权的普通本机目录

本机用户 → 浏览器管理页 127.0.0.1:18765
    │ 另一份管理凭证
目录授权、操作总开关、逐项审批、备份恢复、隧道配置
```

这不是图片或可执行架构文件，而是接口职责说明。端口可由启动参数修改。管理端与 MCP 端各自认证；MCP 路由不承载 `/api/action`。第三方网站不应能靠浏览器普通跨站请求触发审批。服务验证 Host、Origin、Authorization、Content-Length 和 MIME/Accept 等约束，没有公开 CORS。

官方隧道是传输层，不改变内容出站事实、账号权限或产品日志政策；本机只监听 localhost 也不等于远程内容绝不外泄。来源：<https://developers.openai.com/api/docs/guides/secure-mcp-tunnels>。

| 文件 | 主要职责 |
|---|---|
| `app.py` | 启动、状态目录、实例锁、stdio/HTTP 模式、正常退出 |
| `bridge/http_server.py` | 两个 loopback listener、管理 API、HTTP 校验、本机自检 |
| `bridge/protocol.py` | 工具定义、严格参数校验、JSON-RPC 分发、结构化输出 |
| `bridge/security.py` | 根目录授权校验、相对路径约束、敏感名称、链接/句柄检查 |
| `bridge/engine.py` | 读取分页、检索游标、操作提案、审批、备份、恢复 |
| `bridge/extractors.py` | 有界文档提取工作进程；不执行 Office 内容 |
| `bridge/store.py` | SQLite 状态、操作持久化、过期与中断恢复、元数据审计 |
| `bridge/tunnel.py` | 官方子进程配置、环境凭证、诊断、健康状态、退出 |
| `bridge/downloads.py` | 下载域名白名单、哈希检查、安全解包 |
| `bridge/windows.py` | 固定原生选择器调用及 DPAPI；不作为 MCP 工具暴露 |
| `web/` | 中文界面、审批内容展示、状态轮询 |

## 3. MCP 工具契约

统一响应的 `structuredContent` 为 `{ok, data, error?}`；文本 content 是同一对象的 JSON 表示。业务失败用 `isError=true` 并给出 `error.code/message`，不把原始文件路径或堆栈作为远程错误输出。输出架构中的 `data` 为对象，各具体字段由对应方法返回，不伪称所有业务字段都已静态约束。

| 工具 | 必要输入 / 常用参数 | 结果与边界 |
|---|---|---|
| `get_status` | 无 | 授权别名、root_id、模式、限制；不返回本机绝对路径 |
| `list_files` | root_id、path、offset、limit 可选 | 直属项；next_offset；过滤和截断提示 |
| `search_files` | query 必填；root_id/path/mode/cursor/limit | 文件名/正文子串；next_cursor 与覆盖状态 |
| `read_file` | path 必填；root_id/start_line/line_count/expected_sha256 | 提取行、哈希、下一段、格式警告、截断标记 |
| `get_operation` | operation_id | pending/completed/failed 等状态；执行结果在 result 内 |
| `propose_write_file` | path、content、reason；覆盖须 expected_sha256 | 仅 pending 提案；本机审批 |
| `propose_move_file` | path、destination、reason | 同根单文件、同扩展名、不覆盖 |
| `propose_create_directory` | path、reason | 新建一个子目录提案；父目录已存在 |
| `propose_trash_file` | path、reason | 单文件进入程序回收区的提案 |

只有一个授权目录时 root_id 可以省略；多个目录必须明确选择。客户端不能通过绝对路径指定新授权范围。读取续页提供上一段 SHA-256，防止跨文件版本拼接；检索游标则只固定候选路径，不保证所有文件内容同一时刻快照。

全局操作关闭时只发现 5 个只读工具；开启时发现 9 个。协议声明 `listChanged=false`，本服务不发送主动工具变化通知；必须在 ChatGPT 端刷新发现信息。服务端始终再次校验开关，拒绝缓存的旧写工具调用。

## 4. 操作状态机与幂等性

```text
明确请求 → 本机开关和目录权限校验 → 创建 pending 提案
pending → 本机拒绝 → rejected
pending → 超时 / 停用 / 暂停 / 撤销授权 → expired / cancelled
pending → 本机核对完整文件名 → executing
executing → 验证版本、保存备份、执行成功 → completed
executing → 失败 → failed（可能 state_unknown / partial_effects_possible）
executing → 进程异常退出 → 下次启动标记 interrupted，不自动重放
```

工具支持可选 `request_id`；未提供时对提案内容、目标版本、原因等计算请求指纹。重复 pending 返回原操作；终态请求标识不会被复用为新操作。新明确请求使用新 request_id。部分操作在检验原文件阶段就发现状态已改变而返回冲突，也不应无脑重试。

本机审批与模型提案不是同一个授权面。远程工具无法批准提案、改变根目录、打开操作权限、恢复备份或输入隧道密钥。

覆盖以同目录临时文件 + replace 完成；新建和移动目标使用独占创建避免覆盖已有文件。移动使用“复制到独占新目标并 fsync，再核验源版本、删除源”的方式；异常时可能留有目标副本，因此明确披露部分效果，不声称所有操作均为跨步骤原子事务。重命名/移动也不保证保留 ACL、ADS、时间戳等全部系统属性。

## 5. 保护措施与它们不解决的问题

| 保护 | 具体实现 | 边界 |
|---|---|---|
| 明确目录授权 | 最多 12 个不重叠根；仅本机可增删；保存文件系统身份 | 不扫描普通正文里所有秘密；被授权内容仍由用户负责判断 |
| 路径约束 | 拒绝绝对路径、上级引用、ADS、设备名、敏感目录、隐藏名称 | 名称过滤可能误伤，也不能代替保密审查 |
| 链接防护 | 逐层 lstat、拒绝重解析点与多重硬链接，读取后核验句柄最终路径 | 不是对同用户恶意进程的完备 OS 沙箱；竞态无法绝对消除 |
| 分离接口 | 两个 loopback 端口，两份独立随机凭证；MCP 无管理路由 | 被同一 Windows 用户控制的其他程序不在强隔离边界之外 |
| 浏览器防护 | Host/Origin 检查、无 CORS、CSP、安全响应头；正文使用 textContent | 本轮仅验证头字段与 DOM 行为，原生浏览器 HTTP/CSP 部署须本机验收 |
| 文档解析 | 独立子进程、有界输入、超时、ZIP/XML 检查、不执行宏 | PDF/Office 为不可信输入；Windows 不提供强内存/系统调用沙箱 |
| 操作保护 | 双开关 + 本机逐项审批 + 版本校验 + 原始字节备份 | 用户批准恶意内容仍可能造成损失；备份也可能包含敏感信息 |
| 凭证 | 内存默认；可选 Windows 用户 DPAPI；profile 引用 env | 进程内存、用户账户被攻破仍可能暴露；加密不等于隔离 |
| 安装 | 官方 HTTPS 来源、固定或官方公布 SHA、检查归档路径 | 哈希不等于代码审计；未核验发布来源就接受哈希没有意义 |

没有远程 shell、任意系统命令、任意网络 URL 抓取或整目录删除。但本机安装/原生文件选择器会执行程序内固定代码，不能把“不提供远程命令工具”误写成进程完全不调用系统组件。

## 6. 存储、日志与保留

默认 Windows 状态目录 `%LOCALAPPDATA%\LocalFolderBridge`，Linux 测试状态另选临时目录。正式状态包括 SQLite 数据库、实例锁、运行期管理凭证文件、可选 DPAPI 密文、生成的隧道 profile、下载的官方连接组件和备份。

常规审计不保存正文、搜索词或运行密钥；记录时间、来源、动作、root_id、相对路径与结果。UI 展示最近 80 条，数据库按近期约 5,000 条裁剪审计。提案的拟写入正文在待审批时必须持久化；处理结束后从操作 JSON 逻辑移除，不是数据库文件层面的安全擦除保证。备份保存原始文件内容，本身必须按敏感资料保护。

源文档提取结果在内存有界缓存，并可能在解析期间以受控临时文件传给工作进程；这不是“任何字节都绝不落临时磁盘”的系统。凭证不会嵌入文档、交付包或下载配置示例。不要分享完整状态目录用作普通诊断附件。

备份无自动清理，总额 1 GiB；原始字节哈希验证后才恢复。备份不是历史版本服务，不保存所有元信息，也不替代可靠的独立备份方案。

## 7. 资源限制

| 项目 | 限制 |
|---|---|
| 单文件输入 | 25 MiB |
| 文本总提取 | 1,000,000 字符 |
| 单次读取 | 最多 400 提取行、约 40,000 字符 |
| 单行拆分 | 长行按 4,000 字符拆分 |
| 解析进程 | 单文件约 12 秒超时；Linux 可用时设内存限制，Windows 不宣称同等限制 |
| 目录列表 | 最多收集 20,000 项，截断时标明 |
| 搜索候选 | 最多 5,000 文件、3,000 目录，收集有时间预算 |
| 搜索每批 | 最多 100 候选，常规时间预算 5 秒；单次解析有独立超时 |
| 搜索状态 | 最多 8 份，10 分钟过期 |
| 操作提案 | 最多 30 条 pending，15 分钟到期 |
| 文本写入 | 256 KiB UTF-8 |
| 并发请求 | HTTP 线程槽 24；隧道转发上限配置 4 |
| HTTP 请求体 | 512 KiB |

到达限制时应缩小范围、继续分页或在本机另行处理，不把有限搜索包装成“全盘搜索无遗漏”。

## 8. 组件安装与版本口径

Windows 引导固定 Python 3.13.15 官方 zip 和两种架构哈希；只有找不到合适环境时才下载。PDF 固定 pypdf 6.18.1 wheel 哈希；本轮实测5.9.0 的事实在测试报告独立标明。隧道组件按官方最新 release 选择完整 Windows 资产并校验 digest 或 SHA256SUMS，避免同时匹配 full/runtime-only/runtime-cloudflared 造成歧义。

组件下载在本执行环境因网络 DNS/下载条件不可用，没有取得实际 Windows 二进制；因此交付选择明确的联网引导包，而非虚假的离线 EXE。真实下载、Windows 安全提示、架构匹配和隧道账号链路在用户部署时由手册的验收流程确认。

本项目不是第三方安全审计结论、企业生产准入证明或签名软件保证。业务敏感资料应先按所在组织的资料出站与软件安装要求取得许可。
